# 大一统采集框架成熟度评估

## 总体结论

当前框架已经达到 **工程原型 / MVP 可演示 / 部分平台可生产跑批** 阶段，但还没有达到“所有平台稳定无人值守生产级”的成熟度。

可以现在进入 Stitch 做产品模板和业务展示，因为产品结构、对象模型、任务流、安全边界已经清楚；但展示时应明确区分：

- **已可跑平台**：Google Maps、Hungry Panda、Fantuan、GrabFood、OpenRice、KeeTa 的统一入口或平台脚本已存在。
- **已验证能力**：门店注册表、统一任务 DSL、平台能力矩阵、只读安全策略、Google Maps 近 7 天评论采集。
- **待补齐能力**：Mfood executor、统一质量报告、全平台 checkpoint、失败重试、统一 normalized export。

## 硬性指标评估

| 指标 | 当前成熟度 | 评分 | 判断 |
|---|---:|---:|---|
| 准确率 | 中高 | 7/10 | API/DOM 平台准确率高；视觉/OCR 只适合兜底。Google Maps 已支持展开全文和译文，但公开页面布局变化仍需监控。 |
| 执行力 | 中高 | 7/10 | 已有平台脚本和统一 executor；美国 Google Maps 已跑出 39 店 203 条近 7 天评论。长任务恢复机制还需加强。 |
| 效率 | 中 | 6/10 | 分国家分段可控；浏览器自动化慢于 API。后续应优先接口捕获、并发和 checkpoint。 |
| 召回率 | 中 | 6/10 | 对已知门店和有链接平台召回较好；对需要后台筛选/动态加载的平台仍依赖具体 executor。 |
| 适用性 | 高 | 8/10 | 适合多国家、多平台、跨语言评论采集；不适合完全无人干预处理验证码/登录风控。 |
| 集成度 | 中高 | 7/10 | DSL、注册表、能力矩阵、executor 已打通；还需统一 normalized schema 和质量报告聚合。 |
| 安全性 | 高 | 8/10 | 已明确只读边界，默认禁止回复、保存、删除、提交；需要在 UI 层继续隐藏高风险按钮。 |
| 可审计性 | 中 | 6/10 | 有原始 JSON/CSV 和错误输出；还需 run_id、checkpoint、执行日志、失败样本库。 |

## 是否满足现在做 Stitch 模板

满足。原因：

1. **产品对象已明确**：Platform、Store、Review、OrderDetail、CollectionTask、QualityReport。
2. **用户流程已明确**：选平台/国家/门店 -> 跑任务 -> 看评论/译文/图片/订单详情 -> 看质量报告。
3. **安全边界已明确**：只读采集，不做回复、保存、删除、提交。
4. **展示数据已存在**：Google Maps 已有真实导出，其他平台已有脚本和字段预留。
5. **工程路线清晰**：后续补 Mfood、checkpoint、统一质量报告即可增强生产级能力。

## 暂不应承诺的能力

Stitch 模板和对外展示不要承诺以下内容：

- 所有平台 100% 无人值守。
- 自动绕过验证码或风控。
- 自动回复客户。
- 所有平台订单详情 100% 成功读取。
- 纯视觉模型即可稳定采集所有字段。

## 推荐对外表述

推荐说法：

> 这是一个多平台外卖评论统一采集与客诉洞察系统。系统以平台专用执行器为核心，以统一任务 DSL、门店注册表、只读安全策略和质量报告为上层框架，结合 API、DOM、视觉导航和 OCR 兜底，实现跨国家、跨平台的近 7 天评论采集、图片 URL 提取、订单详情读取和外文中文翻译。

不推荐说法：

> 一个纯 AI 自动控制浏览器、适配所有网站、无需平台代码的万能采集机器人。

## 下一阶段生产级门槛

| 门槛 | 必须完成 |
|---|---|
| 稳定运行 | 每个平台支持分段运行和失败重试 |
| 数据统一 | 所有平台导出为同一 normalized schema |
| 质量可见 | 每次运行输出质量报告 |
| 失败可追踪 | 失败门店、失败订单、失败原因可复盘 |
| 登录可控 | 登录态、验证码、人工门流程标准化 |
| 安全可审计 | 所有点击动作记录，写动作默认不可用 |
