## 前情提要

我在一家海外茶饮品牌做运营，手里管着北美、英国、澳洲、韩国五个市场的店铺。外卖平台主要有 Hungry Panda（熊猫外卖）和饭团（Fantuan），每个国家都得单独登录后台看评论。

最痛苦的不是登录，是每天要把各平台的评论数据拉出来——汇总、分析、翻译、生成日报。以前这一套流程没有大半天搞不完，而且全是重复劳动。

直到我给工作电脑装上了 QClaw。

---

## 痛点一：各平台后台逐个登录，眼睛都看花了

Hungry Panda 支持美国、加拿大、澳洲、英国、韩国五个国家的后台。饭团目前主要看加拿大。登录后台不是为了下单，是看用户评论。

每个国家的登录入口、界面语言、操作路径都不一样。以前我得：

1. 打开对应国家后台网址
2. 输账号密码，遇到验证码还得盯着
3. 找到分店列表，逐个进入分店后台
4. 点击"Ratings and reviews"标签
5. 翻页截图或手动抄数据

每天重复五遍，心情烦躁。

现在 QClaw 一句话搞定：

```
把桌面 foodreview_crawler 项目里 hungry_panda_weekly_reviews.py
跑一遍，--region ca --max-reviews 200
结果导出到 exports/hungry_panda_ca_reviews.csv
```

脚本已经写好了，第一次跑时会弹出 Edge 窗口让你完成验证码，之后自动复用登录态。下次再跑就不用管了。

---

## 痛点二：评论格式乱七八糟，合并到崩溃

不同平台导出的评论字段完全不同：

- **Hungry Panda**：Review / Review contents / Image URLs / Order ID / Review time / Child ratings
- **饭团**：用户名 / 头像URL / 评论内容 / 推荐商品 / 评论图片URL / 评分包装口味 / 订单号 / 三角展开后的完整订单详情（商品规格+甜度+单价+佣金+推广费）

两个平台的字段根本没有重叠的列名。每次合并都要先手动对齐，光这一步能搞半小时。

用 QClaw 直接说：

```
把 exports/ 目录下所有 hungry panda 和 fantuan 的评论 CSV 合并到一张表
统一列名为：平台、用户名、评论内容、评分、评论时间、订单号、图片URL、订单详情
只保留最近 7 天的
保存到桌面 5月评论汇总.xlsx
```

项目里已经写好了 `merge_hungry_panda_exports.py`，QClaw 会自动找到并调用，字段映射和去重都是脚本内置处理的。

---

## 痛点三：外文评论翻译要一个个复制到翻译器

北美和澳洲的用户评论全是英文和韩文。要做分析报告，得先把外文翻译成中文。

以前流程是：导出评论 → 复制到 DeepL → 翻译 → 复制回来 → 填表。几百条评论能搞一下午。

现在 QClaw 一句话：

```
把桌面 foodreview_crawler 的 processors 目录里的 pipeline.py 跑一遍
读取 exports/hungry_panda_ca_reviews.csv
对每条评论做翻译和情感分析
结果保存到数据库并导出 Excel
```

`processors/pipeline.py` 里面已经封装好了完整处理链路：
- 翻译（多语言 → 中文）
- 情感分析（正面 / 负面 / 中性）
- 关键词提取
- 回复生成（可选）

每条评论发 3 次 AI 请求（翻译、情感、关键词），脚本内置了 `asyncio.Semaphore(3)` 限流，不会触发 API 限速。

## 痛点四：舆情监控全靠手动搜

除了外卖平台后台，用户还会在百度新闻、微博、知乎、36氪、虎嗅等平台讨论品牌。

以前要一个平台一个平台搜，搜完还得手动整理。今天有没有新负面？有没有热点话题？老板问起来答不上来很尴尬。

QClaw 定时任务来守：

```
每天早上 9 点自动运行桌面 foodreview_crawler 的 sentiment_monitor.py
关键词：喜茶，采集最近 7 天
结果追加写入 exports/sentiment_喜茶_20260506.csv
如果检测到负面舆情，微信通知我
```

`sentiment_monitor.py` 支持：
- 百度新闻 / 微博 / 知乎 / 科技媒体（36氪+虎嗅）四平台联动采集
- 自动去重（跨平台 + 跨历史）
- 同时写 CSV 和 SQLite 数据库（供 Web UI 使用）
- 结果按品牌分组，负面优先排序

## 痛点五：日报要对着数据一个字一个字憋

舆情数据采回来了，还得写日报。以前写日报的流程：

1. 打开今天的 CSV 数据
2. 按品牌分组，算情感分布
3. 挑最重要的文章，每篇写 2 句摘要
4. 拼成 200 字综述
5. 渲染成 Markdown，复制到内部系统

一套下来一个小时没了。而且每次写出来风格还不一样，质量不稳定。

现在 QClaw 说一句：

```
运行 foodreview_crawler 的 publish/daily_publisher.py
读取今天的舆情数据（喜茶、奈雪、蜜雪冰城、茶百道、古茗）
调用 AI 生成综述和精炼摘要
输出保存到 content/posts/2026-05-06.md
同时生成一份 Word 方便打印
```

`daily_publisher.py` 的处理逻辑：
- 精选最高质量文章（必须有真实URL + 发布时间，每品牌最多8篇，全局最多40篇）
- 调用 AI 生成：200字综述 + 每篇文章2句摘要 + 情感趋势 + 热门话题标签
- 统计数据：情感分布、来源分布
- 渲染 Hugo Markdown，自动写入 content/posts/

整个日报从原始数据到可发布文件，全程自动化。

## 实战：月度多平台评论复盘

**场景**：月底要把北美 Hungry Panda + 饭团的评论全部汇总分析，生成给老板看的复盘报告。

第1步：摸清导出文件底数

```
列出 foodreview_crawler/exports 目录里所有评论 CSV 文件
告诉我每个文件的列名、数据量和时间范围
```

项目结构清晰，exports 目录里有按平台和日期命名的文件：
- `hungry_panda_weekly_reviews_20260506_132157.csv`（Hungry Panda CA，周数据）
- `fantuan/fantuan_ca_weekly_reviews_20260506_150438.csv`（饭团 CA，周数据）
- `seg_0_4` 到 `seg_30_32` 的分段文件（分批采集后的中间结果）

第2步：合并整理

```
把 exports 目录下所有 hungry panda 和 fantuan 的评论 CSV
合并为一张汇总表
只保留最近 14 天的记录
按平台、评分、情感分别排序
保存为 exports/5月评论总览.xlsx
```

第3步：数据分析

```
基于 5月评论总览.xlsx
按平台分别统计：总评论数、平均评分、正负面比例、高频关键词
找出差评率超过 10% 的分店
生成一份数据透视表保存为新 sheet
```

第4步：生成复盘文字

```
基于分析结果，写一份 800 字的北美外卖平台月度评论复盘
结构如下：
- 整体概况：总评论数、各平台分布、综合情感趋势
- 分平台表现：Hungry Panda vs 饭团，逐一分析
- 问题诊断：差评率偏高时段、退款原因分析、用户反馈热点
- 下月建议：至少 3 条可执行的优化方向
语气务实，数据说话，适合给运营总监汇报
```

第5步：保存归档

```
在桌面创建 "5月北美评论复盘" 文件夹
把 5月评论总览.xlsx 和复盘摘要 Word 版本保存进去
摘要同步生成一份 Markdown 发给产品团队
```

五步走完，从原始数据到完整复盘报告。以前要两天，现在 20 分钟。

## 架构是怎么组织的

```
foodreview_crawler/
├── blocks/           # 可复用步骤块
│   ├── human_gate.py   # 验证码人工门
│   ├── navigator.py    # 页面导航
│   └── extractor.py    # 表格解析
├── crawlers/         # 各平台爬虫
│   ├── merchant_backend.py   # 通用后台流程引擎（recipe模式）
│   ├── hungry_panda.py        # Hungry Panda 实现
│   └── ...其他平台
├── core/             # 数据模型 + 数据库
├── platforms/        # 独立平台实现
│   └── fantuan/      # 饭团独立隔离
├── processors/       # 评论后处理
│   ├── pipeline.py    # 翻译→情感→关键词→回复
│   ├── sentiment.py    # 情感分析
│   ├── translator.py   # 多语言翻译
│   └── keywords.py     # 关键词提取
├── publish/          # 日报发布
│   ├── daily_publisher.py  # AI日报生成+Hugo发布
│   └── templates/daily_post.md.j2
├── crawlers/sentiment/  # 舆情采集
│   ├── baidu_news.py
│   ├── weibo.py
│   ├── zhihu.py
│   └── tech_media.py
├── scripts/          # CLI 脚本
│   ├── hungry_panda_weekly_reviews.py
│   └── merge_hungry_panda_exports.py
├── cli.py            # 统一命令行入口
└── config.py         # API 配置（多端点支持）
```

**核心设计思路**：

- **两层分离**：通用层（登录态复用、导航、解析、分页、导出）和平台层（URL、字段映射、文案差异）分开，新增平台只需配平台层差异
- **凭证安全**：密码不写 Git，支持命令行 / 环境变量 / 本地文件三层读取，已被 `.gitignore` 排除
- **只读承诺**：所有脚本不点击任何会修改后台状态的按钮（回复、编辑、删除、发券等）
