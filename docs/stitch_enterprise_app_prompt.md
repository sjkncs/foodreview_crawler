# Stitch 企业应用模板 Prompt

复制以下内容到 Stitch，用于生成第一版产品原型。

---

请设计一个企业级 Web App，名称为：

**海外门店评论统一采集与客诉洞察平台**

## 产品定位

这是一个面向 HEYTEA 海外运营、客服、区域经理和数据团队的 B2B 后台系统。系统统一采集 Hungry Panda、Fantuan、GrabFood、Mfood、KeeTa、Google Maps、OpenRice 等平台的近 7 天评论，自动展开全文、提取评论图片 URL、读取只读订单详情、翻译外文评论，并输出质量报告和客诉洞察。

请使用专业、清晰、可信赖的数据平台风格。主色使用 HEYTEA 绿色，搭配灰白背景和少量风险红/警示橙。整体风格类似企业级运营控制台，而不是消费级 App。

## 重要安全约束

界面中必须体现：

- 系统只做只读采集。
- 禁止回复客户、保存、删除、提交、支付、修改门店配置。
- 遇验证码、登录异常、疑似写动作时进入人工门暂停。
- 所有任务都有审计日志和质量报告。

不要设计“自动回复客户”“删除评论”“提交回复”作为主功能。

## 页面 1：首页 Dashboard

布局：

- 顶部导航：Dashboard、采集任务、门店覆盖、评论工作台、平台能力、质量报告、设置。
- 顶部右侧：本周时间范围、导出按钮、用户头像。
- 第一行 6 个指标卡：
  - 本周评论数
  - 负面评论数
  - 低评分订单
  - 有图评论
  - 已翻译评论
  - 失败门店
- 第二行：
  - 左侧折线图：近 7 天评论量和负面率。
  - 右侧平台状态卡：Google Maps、Hungry Panda、Fantuan、GrabFood、KeeTa、OpenRice、Mfood。
- 第三行：
  - 国家 × 平台矩阵，显示采集状态：成功、部分成功、失败、待接入。
  - 最新风险评论列表，显示门店、平台、评分、关键词、评论摘要。

关键视觉：

- 成功状态绿色。
- 部分成功橙色。
- 失败红色。
- 待接入灰色。

## 页面 2：采集任务 Collection Tasks

功能：

- 展示任务列表。
- 创建新任务。
- 查看任务执行日志。
- 分段运行国家、账号、门店。

任务表字段：

- 任务 ID
- 平台
- 国家/地区
- 账号标签
- 门店范围
- 时间范围
- 模式：API / DOM / Hybrid / Visual fallback / OCR fallback
- 状态
- 评论数
- 失败数
- 开始时间
- 导出文件

新建任务抽屉字段：

- 平台选择：Google Maps、Hungry Panda、Fantuan、GrabFood、Mfood、KeeTa、OpenRice。
- 国家选择：美国、加拿大、澳大利亚、英国、韩国、香港、澳门、新加坡、马来西亚。
- 门店范围：全部门店、按 JDE、按门店名、按链接。
- 时间范围：近 7 天、自定义日期。
- 字段选择：评分、评论、译文、图片 URL、订单 ID、订单详情、商品明细、原始 JSON。
- 安全模式：默认开启，不可关闭，只读采集。
- 运行方式：立即运行、分段运行、仅 dry run 验证。

## 文案风格

使用中文界面，必要的平台名称保留英文。文案简洁、明确、偏企业级。

主标题：

海外门店评论统一采集与客诉洞察平台

副标题：

统一采集多平台近 7 天评论，自动展开全文、提取图片与订单详情，并完成外文中文翻译。

主按钮：

- 新建采集任务
- 查看质量报告
- 导出本周数据

## 设计要求

- 采用响应式 Web Dashboard。
- 表格信息密度高，但保持可读性。
- 重要风险评论突出显示。
- 每个采集状态都要可追溯到任务和导出文件。
- 不要做移动端优先；优先桌面端运营后台。
