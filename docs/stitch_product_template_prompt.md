# Stitch 产品原型模板 Prompt

## 用途

用于在 Google Stitch / 其他 AI UI 设计工具中生成“海外门店评论采集与客诉洞察平台”的 Web App 原型。该模板只描述产品体验，不替代后端采集代码。

## 核心定位

请设计一个企业级 Web App：用于统一采集 HEYTEA 海外门店在 Hungry Panda、Fantuan、GrabFood、Mfood、KeeTa、Google Maps、OpenRice 等平台的近 7 天评论，自动提取评论内容、评分、图片 URL、订单详情，并将外文评论翻译为中文，最终形成可审计的客诉分析和门店运营看板。

设计风格：专业、清晰、可审计、偏企业数据平台；主色使用 HEYTEA 绿色和中性色；布局偏 B2B 后台，不要消费级社交风格。

## 信息架构

生成 6 个页面：

1. **总览 Dashboard**
   - 指标卡：总评论数、负面评论数、低评分订单数、有图评论数、已翻译评论数、采集失败门店数。
   - 趋势图：近 7 天评论数量、负面率、平均评分。
   - 国家/平台矩阵：国家 × 平台，显示采集状态、评论数、失败数。
   - 风险列表：最新负面评论、食品安全关键词、服务态度关键词、订单详情缺失项。

2. **任务中心 Collection Tasks**
   - 任务表：平台、国家、账号标签、门店范围、时间范围、状态、开始时间、导出文件。
   - 创建任务抽屉：平台、国家、门店、时间范围、字段选择、安全模式、运行方式。
   - 显示安全策略：只读、禁止回复、禁止保存、禁止删除、遇验证码暂停。

3. **门店与渠道 Store Coverage**
   - 左侧国家筛选：美国、加拿大、澳大利亚、英国、韩国、香港、澳门、新加坡、马来西亚。
   - 中间门店列表：JDE、门店名、国家、Google Maps 链接、外卖平台链接、最近采集时间。
   - 右侧门店详情：平台覆盖情况、最近评论、图片 URL、订单详情覆盖率。

4. **评论工作台 Review Workbench**
   - 评论表：平台、国家、门店、评分、评论时间、用户、原文、中文译文、图片 URL、订单 ID、情感标签。
   - 支持筛选：近 7 天、低评分、有图、外文、负面、食品安全关键词。
   - 右侧详情面板：完整评论、Google 译文/AI 译文、图片预览、订单明细、原始数据片段。

5. **平台能力矩阵 Platform Matrix**
   - 表格展示每个平台的能力：登录方式、采集策略、订单详情、图片 URL、视觉导航用途、当前状态。
   - 每个平台可展开：安全边界、字段映射、失败样本、下一步计划。

6. **质量报告 Quality Report**
   - 指标：字段完整率、订单详情覆盖率、图片 URL 覆盖率、重复率、越界数据数、人工门次数、错误数。
   - 错误列表：平台、门店、错误阶段、错误原因、建议处理动作。
   - 导出按钮：JSON、CSV、Excel。

## 关键交互

- 所有“采集”动作必须显示 safe mode 标签。
- 高风险动作按钮不可出现，例如回复客户、保存、删除、提交。
- “打开订单详情”应标记为只读。
- 评论图片 URL 要能复制，并支持图片预览。
- 外文评论要同时显示原文和中文译文。
- Google Maps 评论需要显示“已展开全文”和“已读取译文”状态。
- 任务执行支持分段：按国家、账号、门店分批运行，避免长任务阻塞。

## 数据对象

请在 UI 中体现以下对象：

- Platform：平台。
- Country：国家/地区。
- Store：门店，包含 JDE、名称、链接、平台覆盖。
- CollectionTask：采集任务。
- Review：评论，包含评分、内容、译文、图片 URL、订单 ID。
- OrderDetail：订单详情，包含商品、规格、价格、数量。
- QualityReport：质量报告。
- SafetyPolicy：只读安全策略。

## 首页文案

标题：海外门店评论统一采集与客诉洞察平台

副标题：统一采集多平台近 7 天评论，自动展开全文、提取图片与订单详情，并完成外文到中文翻译。

主按钮：

- 新建采集任务
- 查看质量报告
- 导出本周数据

## 不要生成的内容

- 不要出现“自动回复客户”作为主功能。
- 不要出现“删除评论”“提交回复”“修改订单状态”等写入型动作。
- 不要把视觉模型描述成唯一采集方式；应体现 API / DOM / 视觉导航 / OCR 的混合策略。
